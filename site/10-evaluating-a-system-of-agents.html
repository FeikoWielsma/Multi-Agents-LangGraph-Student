Worked examples to revisit : demo05 · evaluating-agents, demo05b · trajectory-match, demo05d · each-agent, demo05e · pass-at-k.

Made up, not from work. The Aurelia service records, manuals and evaluation cases are fictional.

Step 1The desk and the cases

Run the cell that builds parts_agent, manuals_agent and desk. Read their tool lists, the case ids in SELECTED and the REQUIRED patterns beside each case's answer_contains, then run the check. answer_contains in eval.jsonl mixes alternatives (db-01) with facts that must all appear (mix-01) ; REQUIRED makes every fact explicit and matches numbers on word boundaries. A no-stock 0 counts only next to a stock word, so the 0 in firmware 5.0 does not.

Which six case ids does the cell select, and which of them have more than one required fact?

Step 2Final-answer scores

Write the three lines of score_answer that set used, facts_ok and tools_ok. Check for every required fact in the answer and every expected tool in the messages. Run all SELECTED cases through desk and read desk_results.

How many cases pass both facts_ok and tools_ok in your run?

Step 3Trajectory match

Run the live man-01 comparison against the full reference (question, call, tool result, answer) and the short_reference (question and call). Strict compares the whole message sequence, roles and count included. Fill trajectory_match_mode in the fixture loop to compare strict and unordered, keeping tool_args_match_mode="ignore". Run the three fixtures, then the check : reversed_calls reorders two calls inside one message, split_reversed puts the same calls in two messages in reverse order, and one drops a call.

Why does strict fail on the short reference, and how do the two modes score reversed_calls, split_reversed and one?

Step 4One score per agent

Fill the two agent blanks in per_agent with the specialist for db_case and the specialist for man_case. Run the mixed-case calls and compare each specialist's row with desk_mix, then run the check. tools_ok is a policy check : a specialist can answer correctly outside its lane.

Which mix-01 rows pass facts_ok but fail tools_ok, and is their answer wrong?

Step 5Three runs

Run the desk twice more on the six cases ; step 2 counts as the first run. Write the two counts : pass_at_k counts cases where at least one run passes and pass_hat_k cases where all three pass (Anthropic, "Demystifying evals for AI agents", January 2026). Run the check.

Which cases pass in some runs and fail in others, and how far apart are pass@3 and pass^3?
